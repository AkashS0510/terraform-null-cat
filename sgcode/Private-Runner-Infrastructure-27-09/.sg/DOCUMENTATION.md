## 3. Module Structure

### Root Module (`/`)
Calls two child modules and exposes variables:
- `module.iam_instance_profile` — a singleton, instantiated once with fixed configuration
- `module.key_pair` — a for_each module, instantiable per key pair from `var.key_pairs` (currently contains only `adis_key_pair`)

### `modules/iam_instance_profile/`
**Purpose**: Wraps `aws_iam_instance_profile` resource.
- **Resource**: `aws_iam_instance_profile.this`
- **Variables**:
  - `name` (string): Instance profile name
  - `role` (string): Associated IAM role name
- **Outputs**:
  - `name`: Profile name
  - `arn`: Profile ARN

### `modules/key_pair/`
**Purpose**: Wraps `aws_key_pair` resource with lifecycle rules.
- **Resource**: `aws_key_pair.this`
- **Variables**:
  - `key_name` (string): SSH key name
  - `public_key` (string, non-sensitive): Public key content
- **Special Logic**: 
  - `lifecycle { ignore_changes = [public_key] }` prevents drift — AWS does not return the public key after creation (write-only), so comparison would always fail
- **Outputs**:
  - `key_name`: Key name
  - `key_pair_id`: Key pair ID

### `modules/instance/` (Not Called)
Code exists but is not instantiated from root. Contains `aws_instance.this` with configurable metadata_options, root_block_device, and lifecycle rules (ignoring user_data changes). Available for future use if EC2 instances become individually manageable.

### `modules/network_interface/` (Not Called)
Code exists but is not instantiated from root. Contains `aws_network_interface.this` with configurable subnet, private IPs, security groups. Available for future use if ENIs become individually manageable.

## 4. How Import Works

The `imports.sh` script maps each Terraform address to its cloud resource ID and runs the Terraform `import` command once:

```bash
"$1" import -var-file environments/sg.tfvars 'module.iam_instance_profile.aws_iam_instance_profile.this' 'Neha_Private_Runner-runner-instance-profile'
"$1" import -var-file environments/sg.tfvars 'module.key_pair["adis_key_pair"].aws_key_pair.this' 'adis-key-pair'
```

**What this does:**
1. Queries AWS API to fetch the resource's current state
2. Writes it into the Terraform state file (`.terraform/state`)
3. Links that state entry to the Terraform address

**Do not re-run** `imports.sh` unless state is completely lost. To re-import a single resource:

```bash
tofu import -var-file environments/sg.tfvars 'module.iam_instance_profile.aws_iam_instance_profile.this' 'Neha_Private_Runner-runner-instance-profile'
```

or

```bash
tofu import -var-file environments/sg.tfvars 'module.key_pair["adis_key_pair"].aws_key_pair.this' 'adis-key-pair'
```

### Initialize Terraform
```bash

```

This downloads the AWS provider and prepares the working directory.

### Plan Changes
```bash
tofu plan -var-file=environments/sg.tfvars
```

Shows proposed changes. After reconciliation, this outputs `No changes. Your infrastructure matches the configuration`.

### Apply Changes
```bash
tofu apply -var-file=environments/sg.tfvars
```

Applies the planned changes to AWS. (Rarely needed after initial import and reconciliation.)

### Target Another Environment
To manage a different environment (e.g., `dev`, `prod`):

1. **Copy the variables file:**
   ```bash
   cp environments/sg.tfvars environments/dev.tfvars
   ```

2. **Edit the new file** with environment-specific values:
   ```bash
   vim environments/dev.tfvars
   ```
   Update `iam_instance_profile_name`, `iam_instance_profile_role`, and key_pairs as needed.

3. **Plan and apply** with the new file:
   ```bash
   tofu plan -var-file=environments/dev.tfvars
   tofu apply -var-file=environments/dev.tfvars
   ```

**No Terraform code edits are required** — environment switching is purely a `.tfvars` affair.

## 8. Notable Decisions & Caveats

### Imported Resources
- ✅ **`aws_iam_instance_profile`**: Successfully imported as a singleton module.
- ✅ **`aws_key_pair` (`adis_key_pair`)**: Successfully imported with a for_each keyed by logical name (`adis_key_pair`).

### Resources NOT Managed (Not Imported)

#### **`aws_instance` (i-025853cd4314ab1f9)** — ASG-managed, not individually importable
- **Reason for exclusion**: This EC2 instance is part of an auto-scaling group (ASG) and tagged with `aws:autoscaling:groupName = Neha_Private_Runner-private-runner-asg`. AWS provider rejected the import attempt with "Cannot import non-existent remote object" because ASG instances are ephemeral and not individually manageable via Terraform — they are created and destroyed by the ASG controller.
- **Module exists** at `modules/instance/` for future use if standalone EC2 instances need to be managed.
- **Drift**: The instance will continue to exist and be updated by the ASG, but Terraform will not track or manage it.

#### **`aws_network_interface` (eni-06111e22ea34335a6)** — Attached to unmanaged instance, not individually importable
- **Reason for exclusion**: This is the primary ENI (network interface) of the ASG instance above. It was already attached to the instance when discovered, and the provider does not allow importing ENIs that are attached to instances not in state. Since the parent instance cannot be managed, neither can its primary ENI.
- **Module exists** at `modules/network_interface/` for future use if standalone ENIs (e.g., secondary interfaces) need to be managed.
- **Drift**: The ENI will continue to exist with the instance and changes made via the AWS console will not be tracked.

### `lifecycle { ignore_changes }`
- **`module.key_pair["adis_key_pair"].aws_key_pair.this`: `ignore_changes = [public_key]`**
  - **Why**: AWS `ec2:DescribeKeyPairs` API returns the public key as `null` after initial creation. The Terraform provider compares the returned state (null) with the configured value ("placeholder"). Without `ignore_changes`, every `plan` would show a spurious diff, claiming the key needs to be recreated.
  - **Consequence**: The public key value in state will never be re-synced with the cloud. If the key is deleted and recreated externally, Terraform will not detect the change. To force re-import, manually delete the state entry or run `tofu import` again.

### Write-only / Placeholder Attributes
- **`key_pairs.adis_key_pair.public_key = "placeholder"`**: This is a placeholder because AWS does not return the actual public key for security reasons (it is a write-only attribute). The real public key is externally stored or known only to the operator. The `ignore_changes` lifecycle rule prevents Terraform from detecting a "drift" on every plan.

### External References
The following resources are referenced by managed resources but are **not managed** by this code (they live outside the state):
